# 엔지니어링 역할 분담

확정 사양은 구현과 독립 검증이 함께 따르는 계약이다.

| 역할 | 주 책임 | 표준 산출물 |
|---|---|---|
| Chat | 개발자와 의도를 명확히 하고 사양 확정 | 결정 사항, 승인된 사양 변경 |
| WSL Ubuntu + Codex | RTL/FW 구현, Verilator 검사, 벤더 CLI 빌드, ModelSim/XSim 실행, 근거 정제, 엔지니어링 보고서 | 소스 변경, 재현 가능한 근거 |
| Antigravity | 사양 기반 독립 TB/DV 작성 | 테스트, assertion, coverage, 리뷰 결과 |
| Windows Work | 검토 완료 근거를 이용한 표현·편집, 선택적 GUI 작업 | 포트폴리오, PDF/PPT, 면접 자료 |

원본 실행 산출물은 `$RUN_ROOT`, 검토·정제된 공개 근거는 공개 저장소에 둔다. 라이선스 또는 생성물이 포함된 벤더 상태는 `$VENDOR_ROOT`에 둔다. Windows Work를 엔지니어링 사실의 유일한 보관 장소로 만들거나 원본 근거를 덮어쓰면 안 된다.

RTL과 DV가 불일치하면 먼저 사양을 명확히 한다. 어느 쪽도 상대 구현에 맞추기 위해 동작을 암묵적으로 바꾸지 않는다.
