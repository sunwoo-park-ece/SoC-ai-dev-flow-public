## 1. 목적

이 문서는 DE10-Lite의 10개 slide switch를 위한 전용 APB input peripheral을 정의한다.

목표 구조는 legacy `APB_GPIO`에서 switch 역할을 분리하고 다음을 제공한다.

- 10개 switch input
- PCLK domain 2FF synchronization
- synchronized current-state readback
- switch별 sticky change pending
- switch별 IRQ enable
- 향후 PLIC에 연결 가능한 active-high level IRQ
- deterministic reset / W1C semantics
- 최소 APB register interface

이 블록은 board-specific input peripheral이며 general-purpose GPIO가 아니다.

## 2. 주소 및 APB slot

P04 이전 baseline은 legacy `APB_GPIO`를 통해 `SW[9:0]`을 읽었다. P04 이후 active switch ownership은 이 peripheral이다.

확정된 target assignment:

```text
SW_BASE  = 0x4008_0000
APB slot = PSEL[8]
```

Target APB는 `PSEL[15:0]`을 사용하고, 기존 slot 0~7 주소는 유지한다. Slot 8은 SW, slot 9는 LED, slot 10~15는 Reserved이다.

이 주소는 P04 이후 active assignment다. `memory_map.md`가 시스템 주소 map의 정본이다.

## 3. 권장 module interface

```text
module APB_SW

Inputs:
  PCLK
  PRESETn
  PADDR[31:0]
  PWRITE
  PSEL
  PENABLE
  PWDATA[31:0]
  SW[9:0]

Outputs:
  PRDATA[31:0]
  PREADY
  irq
```

구조:

```text
SW[9:0]
   |
2FF synchronizer
   |
 sw_sync
   |\
   | +--> change detect -> IRQ_PENDING -> & IRQ_ENABLE -> OR -> irq
   |
   +----> SW_DATA
```

Event detector와 APB-visible state는 동기화 이후 PCLK domain에서 동작한다.

## 4. Width / Physical Mapping

```text
SW_DATA[0] <- SW[0]
...
SW_DATA[9] <- SW[9]
```

`[9:0]`만 구현하며 read `[31:10]`은 0이다.

## 5. Canonical Register Map

| Offset | Absolute address | Register | Access | Reset | 의미 |
|---:|---:|---|---|---:|---|
| `0x00` | `0x4008_0000` | `SW_DATA` | RO | sampled state | synchronized switch state |
| `0x04` | `0x4008_0004` | `SW_IRQ_ENABLE` | R/W | `0x000` | per-switch IRQ mask |
| `0x08` | `0x4008_0008` | `SW_IRQ_PENDING` | R / W1C | `0x000` | sticky change event |

Exact offset decode를 사용하고 legacy register mirroring은 만들지 않는다.

이전 target 초안은 unknown offset에 zero/no-effect를 제안했다. 승인된 A2와 active P04 동작이 이를 대체하여 비정규 offset/size는 SW side effect 없이 APB ERROR를 반환한다.

## 6. `SW_DATA`

```text
SW_DATA[i] = sw_sync[i]
```

CPU는 raw asynchronous pin을 직접 읽지 않는다. `SW_DATA` write는 효과가 없다.

## 7. Input Synchronization

각 switch는 최소 2FF synchronizer를 통과한다.

```text
SW[i] -> sync_ff1[i] -> sync_ff2[i] = sw_sync[i]
```

State readback과 event detector는 `sw_sync`만 사용한다.

### 7.1 Debounce

최소 target contract에는 full mechanical debounce를 넣지 않는다. Sticky pending이 pending 유지 중 반복 transition을 합칠 수 있기 때문이다. Board test에서 clear 직후 재발생이 문제가 되면 후속 revision으로 debounce를 추가할 수 있다.

## 8. Change Detection

```text
change_event = sw_sync ^ sw_prev
```

`0->1`, `1->0` 모두 event이다. Rising/falling selectable 방식이 아니라 any-change 방식이다.

## 9. Reset / Warm-Up

Reset:

```text
SW_IRQ_ENABLE  = 0
SW_IRQ_PENDING = 0
irq            = 0
```

Reset 해제 시 이미 high인 switch 때문에 false event를 만들면 안 된다. Synchronizer가 valid state를 확보한 뒤 최초 arm 시:

```text
sw_prev <- sw_sync
```

만 수행하고 pending은 set하지 않는다.

## 10. `SW_IRQ_ENABLE`

```text
0 = local irq에서 mask
1 = irq source로 enable
```

Pending capture 자체는 enable과 독립이다.

## 11. `SW_IRQ_PENDING`

Synchronized change가 해당 sticky pending bit를 set한다. Software는 W1C로 clear한다.

동일 cycle W1C와 신규 event가 겹칠 때 required behavior:

```text
pending_next = (pending & ~w1c_mask) | change_event
```

즉 event set-dominant이다.

## 12. IRQ Contract

```text
irq = |(SW_IRQ_PENDING & SW_IRQ_ENABLE)
```

Active-high level signal이며 enabled pending이 남아있는 동안 asserted 상태를 유지한다.

### 12.1 PLIC boundary

이 spec은 local `irq` wire까지만 정의한다. PLIC source ID, priority, threshold, claim/complete, CPU CSR behavior는 future PLIC spec이 소유한다.

PLIC이 없는 cleanup 단계에서는 `sw_irq` wire가 존재해도 CPU에는 연결하지 않을 수 있다.

## 13. 향후 ISR service 순서

```text
1. PLIC claim
2. SW_IRQ_PENDING read
3. SW_DATA read
4. event 처리
5. serviced pending W1C
6. local sw_irq deassert
7. PLIC complete
```

Local pending이 남은 상태에서 complete하면 source가 다시 제시될 수 있으며 level IRQ의 정상 동작이다.

## 14. APB Behavior

```text
PREADY = 1
```

MMIO는 naturally aligned 32-bit access만 normative하다.

## 15. Firmware Contract

권장 초기화:

```text
1. 필요하면 SW_DATA initial state read
2. SW_IRQ_ENABLE = 0
3. SW_IRQ_PENDING에 0x3FF W1C
4. 원하는 enable mask write
```

Polling-only firmware는 enable을 0으로 유지하고 `SW_DATA`만 읽으면 된다.

Pending은 event counter/queue가 아니라 “변경이 있었다”는 sticky indication이다.

## 16. GPIO / LED와의 관계

확정된 target board-I/O 구조:

```text
SW[9:0]   -> APB_SW    @ PSEL[8]
LEDR[9:0] <- APB_LED   @ PSEL[9]
GPIO_IO[] <-> APB_GPIO @ PSEL[1]
```

기존 GPIO slot은 **제거하지 않는다.** `APB_GPIO`는 true bidirectional GPIO로 재설계하고 SW/LED board signal과는 연결을 끊는다.

## 17. Verification Requirements

최소 directed verification:

1. reset enable/pending/irq
2. arbitrary static input에서 warm-up false event 없음
3. 10-bit synchronized readback
4. 양방향 change detection
5. multiple pending bits
6. enable=0에서도 pending capture
7. `pending & enable`에 따른 IRQ
8. per-bit W1C
9. event + W1C set-dominant
10. last enabled pending clear 후 IRQ deassert
11. enable mask change
12. exact offset decode
13. `PREADY=1`
14. top-level `PSEL[8]` mapping
15. GPIO에 residual SW path가 없음

Board에서는 10개 switch 전체의 current state와 event/IRQ behavior를 확인한다.

## 18. 남은 결정

APB base/slot/width는 더 이상 TBD가 아니다. 남은 항목은:

1. PLIC source ID 및 interrupt-controller policy
2. board test 후 optional debounce
3. 승인된 A2 APB reserved/default-slave ERROR 구현

## 19. Target Invariants

1. `SW_BASE = 0x4008_0000`, `PSEL[8]`이다.
2. Target APB는 16-slot 구조다.
3. `APB_SW`가 `SW[9:0]` 전체를 소유한다.
4. CPU는 raw asynchronous SW를 직접 읽지 않는다.
5. `SW_DATA`는 synchronized state이다.
6. synchronized logical change는 sticky pending을 set한다.
7. pending capture는 enable과 독립이다.
8. simultaneous W1C/event는 set-dominant이다.
9. `irq = |(pending & enable)`인 active-high level signal이다.
10. reset/warm-up에서 false pending을 만들지 않는다.
11. PLIC source ID는 dedicated PLIC spec 전까지 미정이다.
12. 이 peripheral은 general-purpose GPIO가 아니다.
