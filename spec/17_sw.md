## 1. Purpose

This document defines the dedicated APB peripheral for the ten DE10-Lite slide switches.

The target design separates switch input handling from the legacy `APB_GPIO` block and provides:

- ten dedicated switch inputs,
- destination-domain synchronization,
- software-visible synchronized switch state,
- sticky per-switch change-pending bits,
- per-switch interrupt-enable bits,
- a PLIC-ready active-high level interrupt output,
- deterministic reset and event-clear behavior,
- a minimal APB register contract.

This block is board-specific input logic, not a general-purpose GPIO controller.

## 2. Architectural Status and Address Ownership

The pre-P04 baseline obtained `SW[9:0]` through legacy `APB_GPIO`. P04 moves active switch ownership to this peripheral.

The APB expansion and board-I/O architecture are now approved by `board_io_architecture.md`:

```text
SW_BASE  = 0x4008_0000
APB slot = PSEL[8]
```

The target APB subsystem uses `PSEL[15:0]`; existing slots 0 through 7 retain their current addresses, slot 8 is SW, slot 9 is LED, and slots 10 through 15 are reserved.

These addresses are the active P04 assignments. `memory_map.md` remains the system address-map authority.

## 3. Target Module Boundary

Recommended module interface:

```text
module APB_SW

Inputs:
  PCLK
  PRESETn
  PADDR[31:0]
  PWRITE
  PSEL
  PENABLE
  PWDATA[31:0]
  SW[9:0]

Outputs:
  PRDATA[31:0]
  PREADY
  irq
```

Conceptual topology:

```text
DE10-Lite SW[9:0]
       |
       v
 +------------------+
 | 2FF synchronizer |
 +--------+---------+
          |
          v
    sw_sync[9:0]
          |
     +----+--------------------+
     |                         |
     v                         v
 SW_DATA                 change detector
                              |
                              v
                     IRQ_PENDING[9:0]
                              |
                     & IRQ_ENABLE[9:0]
                              |
                              v
                         reduction OR
                              |
                              v
                             irq
                              |
                         future PLIC
```

The event detector and APB-visible state operate in the `PCLK` domain after synchronization.

## 4. Width and Physical Mapping

The peripheral owns all ten DE10-Lite slide switches:

```text
SW_DATA[0] <- SW[0]
...
SW_DATA[9] <- SW[9]
```

Only bits `[9:0]` are implemented. Reads return zero in bits `[31:10]`; writes ignore bits `[31:10]`.

## 5. Canonical Register Map

| Offset | Register | Access | Reset | Meaning |
|---:|---|---|---:|---|
| `0x00` | `SW_DATA` | RO | sampled physical state | synchronized current switch levels |
| `0x04` | `SW_IRQ_ENABLE` | R/W | `0x000` | per-switch interrupt mask |
| `0x08` | `SW_IRQ_PENDING` | R / W1C | `0x000` | sticky per-switch change events |

Canonical absolute addresses are therefore:

```text
0x4008_0000  SW_DATA
0x4008_0004  SW_IRQ_ENABLE
0x4008_0008  SW_IRQ_PENDING
```

Only these offsets are architectural. The implementation shall use explicit offset decode and shall not intentionally reproduce legacy register mirroring.

An earlier draft target proposed zero/no-effect for unknown registers. Frozen A2 and active P04 behavior supersede that draft: noncanonical offsets or unsupported sizes return APB ERROR without a SW peripheral side effect.

## 6. `SW_DATA` Semantics

```text
SW_DATA[i] = sw_sync[i]
```

Software never observes raw asynchronous board pins through this peripheral. Writes to `SW_DATA` have no effect.

## 7. Input Synchronization

Each external switch shall pass through at least a two-flop synchronizer in the destination `PCLK` domain:

```text
SW[i] -> sync_ff1[i] -> sync_ff2[i] = sw_sync[i]
```

Both the software-visible state and change detector consume only `sw_sync`.

### 7.1 Mechanical debounce

A full mechanical debounce filter is not required by the minimum target contract. Sticky pending bits naturally collapse repeated transitions while a pending bit remains set. If board testing shows repeated post-clear events are undesirable, debounce may be added by an approved revision without changing the PLIC-facing level-IRQ model.

## 8. Change Detection

The required event function is:

```text
change_event[9:0] = sw_sync ^ sw_prev
```

Both `0 -> 1` and `1 -> 0` are events. The block uses any-change detection rather than separately programmable rising/falling selection.

## 9. Reset and Synchronizer Warm-Up

Reset shall produce:

```text
SW_IRQ_ENABLE  = 0x000
SW_IRQ_PENDING = 0x000
irq            = 0
```

The design shall not create a false event merely because a switch is already high when reset releases. The event detector shall remain disarmed until synchronized state is valid; initial arming loads:

```text
sw_prev <- sw_sync
```

without setting pending bits.

## 10. `SW_IRQ_ENABLE`

`SW_IRQ_ENABLE[9:0]` controls which captured events contribute to the local interrupt output:

```text
0 = masked from irq
1 = enabled for irq
```

Event capture is independent of the enable mask. A switch change may set `SW_IRQ_PENDING[i]` while `SW_IRQ_ENABLE[i] = 0`.

## 11. `SW_IRQ_PENDING`

Each pending bit is sticky. A synchronized change sets the corresponding bit and software clears selected bits by W1C.

Required simultaneous-clear/event behavior:

```text
pending_next = (pending & ~w1c_mask) | change_event
```

Therefore event set is dominant over software clear for the same bit in the same cycle.

## 12. IRQ Output Contract

The peripheral exposes one active-high level interrupt:

```text
irq = |(SW_IRQ_PENDING[9:0] & SW_IRQ_ENABLE[9:0])
```

The line remains asserted while any enabled pending bit remains set and deasserts only after all enabled pending bits are cleared or masked.

### 12.1 PLIC boundary

This specification defines the local `irq` wire only. It does not allocate a PLIC source ID, priority, threshold, claim/complete behavior, or CPU CSR behavior. Those remain owned by the future dedicated PLIC specification.

Before PLIC integration, the local `sw_irq` wire may exist without a CPU connection.

## 13. Intended PLIC ISR Service Rule

When eventually connected as a level-sensitive PLIC source, the intended service ordering is:

```text
1. PLIC claim
2. read SW_IRQ_PENDING
3. read SW_DATA
4. process events
5. W1C serviced local pending bits
6. allow local sw_irq to deassert
7. PLIC complete
```

Completing the PLIC source while local pending remains asserted may cause immediate re-presentation of the source, which is normal level-interrupt behavior.

## 14. APB Behavior

The target block is always ready:

```text
PREADY = 1
```

Software-visible accesses are naturally aligned 32-bit MMIO operations. No byte-strobe contract is required.

## 15. Firmware Contract

Recommended initialization:

```text
1. optionally read SW_DATA for initial state
2. SW_IRQ_ENABLE = 0
3. W1C SW_IRQ_PENDING with 0x3FF
4. program the desired SW_IRQ_ENABLE mask
```

Polling-only firmware may keep the interrupt-enable mask at zero and read `SW_DATA` directly.

Pending bits indicate that a switch changed; they are not event counters or ordered event queues.

## 16. Relationship to GPIO and LED

The approved board-I/O target is:

```text
SW[9:0]   -> APB_SW   at PSEL[8]
LEDR[9:0] <- APB_LED  at PSEL[9]
GPIO_IO[] <-> APB_GPIO at PSEL[1]
```

The legacy GPIO slot is **retained**, not removed. `APB_GPIO` will be redesigned as a true bidirectional generic GPIO peripheral and disconnected from the board switches and LEDs.

Legacy behavior that shall not be carried into `APB_SW` includes unsynchronized input reads and mixed SW/LED pseudo-GPIO semantics.

## 17. Verification Requirements

Directed RTL verification shall cover at minimum:

1. reset values of enable/pending/irq,
2. no false event during synchronizer warm-up with arbitrary static SW inputs,
3. synchronized data readback for all ten bits,
4. both change directions,
5. independent pending bits for multiple switches,
6. pending capture while IRQ enable is zero,
7. IRQ assertion only from `pending & enable`,
8. per-bit W1C,
9. simultaneous event + W1C set-dominant behavior,
10. IRQ deassertion after the last enabled pending bit clears,
11. enable-mask changes with existing pending bits,
12. exact register-offset decode,
13. `PREADY=1`,
14. top-level `PSEL[8]` and `SW[9:0]` mapping,
15. no residual switch path through `APB_GPIO`.

Board validation shall manually exercise all ten switches and verify current state plus local event/IRQ behavior.

## 18. Remaining Open Decisions

The APB base address and slot are no longer open; they are fixed by `board_io_architecture.md`.

Remaining integration decisions are:

1. final PLIC source ID and interrupt-controller policy,
2. optional debounce after board testing,
3. implementation of frozen A2 reserved/default-slave ERROR behavior inherited from the target APB subsystem.

## 19. Target Invariants

Once implemented:

1. `SW_BASE = 0x4008_0000` and the peripheral is selected by `PSEL[8]`.
2. The APB subsystem uses the approved 16-slot target architecture.
3. `APB_SW` owns all ten `SW[9:0]` inputs.
4. Software never reads raw asynchronous switch pins.
5. `SW_DATA` reports synchronized current state.
6. Any synchronized logical transition sets the corresponding sticky pending bit.
7. Pending capture is independent of the interrupt-enable mask.
8. Simultaneous W1C and new event is event-set dominant.
9. `irq` is active-high, level-sensitive, and equals `|(pending & enable)`.
10. Reset/warm-up does not create a false pending event.
11. PLIC source ID remains undefined until the dedicated PLIC specification assigns one.
12. This peripheral is not a general-purpose GPIO block.
